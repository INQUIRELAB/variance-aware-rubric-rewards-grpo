## Overview

Deploying large language models in clinical settings is constrained by inference cost, data privacy, and the difficulty of ensuring safe, multi-criteria medical reasoning. General-purpose LLMs can produce plausible but clinically incomplete responses that miss contraindications, confuse differential diagnoses, or express unwarranted certainty. Heart-focused medical question answering is a particularly demanding domain because symptoms like chest pain, dyspnea, and palpitations require conservative guidance, appropriate uncertainty handling, and careful risk assessment.

This repository contains the training and evaluation pipeline for a GRPO-based post-training framework that optimizes a 14B-parameter language model (Qwen3-14B) against physician-written rubric criteria for heart-related medical question answering. The system uses rubric-based reward signals derived from the RaR-Medicine dataset, where each training prompt is associated with a set of positive and negative evaluation criteria authored by clinicians. Rather than using binary pass/fail rewards or a single holistic score, we propose a Variance-Aware Reward Framework that transforms criterion-level judgments into continuous reward signals suitable for reinforcement learning.

On a held-out heart-related subset of HealthBench, the best GRPO variant improves accuracy from 0.362 to 0.502 and F1 from 0.532 to 0.668 relative to the Qwen3-14B base model, while remaining competitive with GPT-OSS-120B (0.508 accuracy, 0.674 F1).

## Approach

The pipeline consists of four stages: data curation, supervised fine-tuning, reinforcement learning via GRPO, and comparative evaluation.

### Data Curation

Training data comes from RaR-Medicine, a dataset of medical questions with reference answers and rubric annotations. Each rubric defines criteria that a good response should satisfy (positive criteria with positive point values) and behaviors it should avoid (negative criteria with negative point values). We filter the full corpus to heart-related queries using a dedicated classifier built on MedGemma 3:27b. The classifier assigns a binary heart-related label along with a theme category (e.g., heart attack, hypertension, arrhythmia) and keyword evidence grounded in the original query text. A keyword verification step ensures that the classifier's decisions are traceable to actual content in the prompt rather than hallucinated associations.

The filtered heart-related subset is augmented with synthetic reasoning traces generated by MedGemma. These traces provide step-by-step clinical reasoning that connects the question to the reference answer, written in continuous prose rather than bullet points. The augmented dataset is then split 50/50 into disjoint subsets for supervised fine-tuning and GRPO training.

Evaluation uses a separate held-out dataset, HealthBench, which provides multi-turn medical conversations graded by 262 physicians across 60 countries with over 48,000 unique rubric criteria spanning seven clinical themes and five behavioral axes.

### Supervised Fine-Tuning (SFT)

The first training stage teaches the model a structured output format that separates reasoning from recommendations. Responses are formatted with explicit `<start_working_out>` / `<end_working_out>` tags for the reasoning trace and `<SOLUTION>` / `</SOLUTION>` tags for the final answer. Instruction tokens (everything before the reasoning section) are masked during training so the model only learns to generate responses, not to memorize prompts. The model uses LoRA adapters (rank 16, alpha 32) targeting all attention and MLP projections, with gradient checkpointing and 4-bit quantization to keep training feasible on academic hardware.

### Group Relative Policy Optimization (GRPO)

The second stage applies GRPO to optimize response quality against rubric-based rewards. GRPO is an RL algorithm that eliminates the need for a separate critic/value model by computing advantages from relative scores within each batch of generated completions. This reduces memory requirements compared to PPO-style methods and fits naturally with reward settings where relative ranking is more reliable than absolute calibration.

For each training prompt, the model generates multiple completions. A judge model (GPT-OSS-120B, accessed via the Groq API) evaluates each completion against every rubric criterion independently, returning a binary present/absent decision per criterion. The criterion-level verdicts are aggregated into positive and negative scores, which are then transformed into a scalar reward through one of two reward shaping functions.

Training focuses on prompts with more than three rubric criteria, filtering out trivially simple examples that would produce uninformative reward signals.

### Reward Functions

A central challenge in applying GRPO to rubric-based tasks is that naive binary rewards (perfect score or zero) produce near-zero variance across batches, collapsing the advantage estimates and preventing learning. Our reward functions address this by preserving partial-credit information and accounting for rubric complexity.

**Hybrid Reward.** This function combines a continuous base reward proportional to the normalized rubric score with a discrete perfection bonus. The base portion (up to 15 points) scales linearly with the fraction of positive criteria met, with a penalty proportional to the fraction of negative criteria triggered. A 5-point bonus is added only when all positive criteria are satisfied and no negative criteria are triggered. This design provides gradient signal for incremental improvements while maintaining a strong incentive for fully correct and safe responses.

**Complexity-Aware Reward.** This function applies a power-law transformation ($\alpha = 1.2$) to the normalized score and scales the result by a logarithmic complexity factor based on the number of rubric criteria. The formula is $r = 20 \times \hat{s}^{1.2} \times (1 + 0.2 \times \log(1 + n_c) / \log(26))$, where $\hat{s}$ is the penalty-adjusted normalized score and $n_c$ is the number of criteria. The convex power curve emphasizes high-quality responses while the complexity scaling acknowledges that prompts with more criteria represent harder evaluation targets.

Both reward functions satisfy the four prerequisites for effective GRPO training: non-zero variance across quality levels, monotonicity with respect to quality, preservation of partial-credit information, and awareness of task complexity.

### Evaluation

The evaluation stage compares the GRPO-trained model against the unmodified Qwen3-14B base and several frontier models hosted via the Groq API: Kimi-K2, Llama-4-Scout-17B, Llama-4-Maverick-17B, Llama-3.3-70B, and GPT-OSS-120B. Each model generates responses to the held-out HealthBench heart-related prompts, and responses are scored against physician-written rubrics using the same criterion-level evaluation pipeline used during training. Metrics include accuracy, precision, recall, and F1.

## Usage

### Prerequisites

The pipeline requires a CUDA-capable GPU with at least 15 GB VRAM. Training was conducted on NVIDIA A100 and H100 GPUs. A Groq API key is required for the LLM judge during GRPO training and for frontier model evaluation.

```bash
pip install unsloth torch pandas numpy datasets trl pydantic seaborn matplotlib scikit-learn groq pyarrow
export GROQ_API_KEY="your-key-here"
```

### Running the Full Pipeline

The main script supports modular execution through command-line flags. Running without flags performs SFT followed by GRPO training with the hybrid reward, then evaluates all models.

```bash
# Full pipeline: SFT + GRPO + evaluation
python "Qwen3-8b (new)_v2.py" --both-sft-grpo --eval-local --eval-groq

# Quick verification (5 SFT steps + 5 GRPO steps + limited eval)
python "Qwen3-8b (new)_v2.py" --smoke-train

# SFT only
python "Qwen3-8b (new)_v2.py" --only-sft

# GRPO only (requires existing SFT checkpoint)
python "Qwen3-8b (new)_v2.py" --only-grpo --reward-type hybrid

# Evaluation only (requires existing checkpoints)
python "Qwen3-8b (new)_v2.py" --only-eval --eval-local --eval-groq

# Run both reward types sequentially
python "Qwen3-8b (new)_v2.py" --both-sft-grpo --reward-type all
```

### Key Options

| Flag | Description |
|------|-------------|
| `--reward-type {hybrid,complexity,all}` | Reward function for GRPO training (default: hybrid) |
| `--sft-steps N` | Override SFT training steps (default: 500) |
| `--grpo-steps N` | Override GRPO training steps (default: 1000) |
| `--eval-samples N` | Number of evaluation samples (default: 500) |
| `--gpu N` | Explicitly select a GPU index |
| `--gpu-failover` | Automatically retry on another GPU after OOM |
| `--skip-smoke-test` | Skip pre-training model verification |
| `--smoke-train` | Minimal pipeline verification (5 steps each) |

### GPU Auto-Selection

The script automatically queries `nvidia-smi` for GPU utilization and selects the GPU with the most free memory and less than 30% utilization. If `--gpu-failover` is enabled and training crashes with an out-of-memory error, the script automatically relaunches itself on the next available GPU with sufficient memory.

## Datasets

**RaR-Medicine** (training): 17,926 training examples with medical questions, reference answers, and rubric annotations. After heart-related filtering with the MedGemma-based classifier, the cardiac subset is split evenly between SFT and GRPO phases. Each rubric criterion includes a text description and a signed point value indicating whether it represents desired behavior (positive) or behavior to avoid (negative).

**HealthBench** (evaluation): A held-out medical evaluation benchmark with rubric annotations from 262 physicians across 60 countries. The heart-related subset is used for all reported metrics. No HealthBench data appears in the training pipeline.

## Results

On the held-out heart-related HealthBench subset, GRPO post-training with the hybrid reward function produces the following improvements over the Qwen3-14B base model:

| Model | Accuracy | F1 |
|-------|----------|-----|
| Qwen3-14B (base) | 0.362 | 0.532 |
| Qwen3-14B + GRPO (hybrid) | 0.502 | 0.668 |
| GPT-OSS-120B | 0.508 | 0.674 |

The GRPO-trained 14B model approaches the performance of GPT-OSS-120B, a model roughly an order of magnitude larger, while supporting local deployment on academic hardware.
